# Story 0017: 今後のADRで決定を一行に絞る

## context

ADR 0005とADR 0012の `decision` には、採用した判断に加えて、実装方法、例外、API、画面挙動が長い箇条書きで並んでいる。
決定そのものを探すには、節全体を読み解かなければならない。

既存ADRは当時の記録として残し、これから作るADRだけを読みやすくする。

## definition of done

- [x] 今後作るADRの `decision` を一行の決定文にするルールが、リポジトリの指示に記録されている。
- [x] 一行に含めない理由、選択肢、リスクの置き場所が示されている。
- [x] 決定の理解に欠かせない条件だけを、補足として残せる。
- [x] 既存ADRの本文を変更していない。

## to do

- [x] ADR作成ルールをADRとして先に記録する。
- [x] `AGENTS.md` に今後の作成ルールを追加する。
- [x] 差分と既存ADRが未変更であることを確認する。
- [x] 機密情報を含まないことを確認してcommitする。

## concern

- 一行を短くすること自体が目的になると、決定の適用範囲まで失われる。
- 補足を許すだけでは、従来の長い箇条書きへ戻る可能性がある。
- 複数の独立した判断を一つのADRへ入れ続けると、一行の決定文が曖昧になる。
