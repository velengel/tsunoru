# Story 0005: 回答のあとに任意のひとことを返す

Status: in progress

Date: 2026-09-02

Product sequence: Story 3

## context

Product Story 2で、回答者は共有URLから名前と全候補の都合を送り、ログインせず回答を完了できるようになった。
ただし、○、△、×だけでは「一人の人が返事をした」感触や、主催者への短い反応を残せない。

First Instructionは、情報量の多さではなく発話そのものに価値を置く。
「調整ありがとう！」「楽しみ！」「肉！」のような短い言葉も歓迎しつつ、回答完了までの必須操作は一つも増やさない。

## definition of done

- 名前と全候補の都合が保存された時点で、ひとことを書かなくても回答完了であることが明確に伝わる。
- 回答完了後の同じ画面から、ログインせず任意のひとことを一件だけ送れる。
- 短い挨拶や自由な内容を歓迎する軽い導線があり、情報提供を強要する説明にしない。
- ひとことを送らず画面を閉じる選択が、失敗や未完了として扱われない。
- 空白だけのひとこと、上限を超える本文、不正なeventまたは回答capabilityはサーバーで保存されない。
- ひとことは、名前や公開された回答IDではなく、回答時に生成した回答capabilityで直前の回答へ結び付ける。
- 生の回答capabilityをDOM、URL、server log、SQLite、`localStorage`へ出さない。
- 同じ送信の再試行でひとことが重複せず、保存失敗時は入力内容が画面に残る。
- 保存後は送信済みであることが明確に伝わり、Story 4の回答サマリーやコメント一覧を先回りして表示しない。
- 320px幅で横スクロールせず、入力、送信、送らず終了する判断をキーボードだけでも完了できる。
- 利用者に見える受け入れテストと、認可・保存境界のtestを実装より先に追加し、期待した理由でREDになる。
- test、Clippy、format、Fullstack build、秘密情報検査が成功する。
- 8081の候補版を検証している間も、検証済みserverを別portで利用できる。

## concern

- 回答capabilityは回答直後のcomponent stateだけにあるため、reloadや別端末から後でひとことを追記できない。Story 3の「回答後」の短い導線を優先し、復旧や編集を暗黙に約束しない。
- コメントを促す表現が強いと、任意入力でも回答が未完了に見える。回答完了の確認を先に置き、閉じてよいことを明示する必要がある。
- 自由入力にはHTMLやscriptに見える文字列、極端に長い本文が入る。表示時のescapeと、clientを信頼しないserver側上限が必要である。
- network応答を保存後に失う場合、再試行で同じひとことを増やしてはいけない。一方、Story 3ではコメント編集を要求していないため、変更再送との境界を決める必要がある。
- 回答者名や内部response IDを認可に使うと、同名回答やrequest改変で別人の回答へひとことを付けられる。回答capabilityの秘密境界を保つ必要がある。
- コメント一覧、回答サマリー、従来型集計表は後続Storyであり、保存の都合だけで通常画面へ先回りさせない。
