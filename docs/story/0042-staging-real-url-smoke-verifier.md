# Story 0042: staging 実 URL smoke 検証を再実行可能にする

## context

staging の health、試用セッション、イベント作成・公開読取・匿名回答を実 URL で確認する手順が個別の手動操作に分散している。リファクタや再配置のたびに同じ受け入れ範囲を安全に再確認できる、秘密値を出さない検証器が必要である。

## definition of done

- 正規 staging URL を対象に health と API の基本セキュリティ応答を確認できる。
- 試用セッションを確立し、合成イベントの作成・公開読取・匿名回答・回答読取を確認できる。
- 毎回異なる合成 ID を使い、成功・失敗・割り込みのすべてでイベント削除を試みる。
- 秘密値を標準出力や証跡へ出さず、失敗時は non-zero で終了する。
- 実 URL 検証の実行方法と結果をレポートへ記録できる。

## to do

- [ ] CLI smoke verifier と安全な設定読込を追加する
- [ ] RED テストで成功・失敗・cleanup 境界を定義する
- [ ] 正規 staging URL で実行し、証跡を記録する
- [ ] Story と README を実装状態へ更新する

## concern

検証は実 staging D1 に合成データを書き込むため、必ずイベント削除を行う。認証情報は環境変数等から読み、引数・ログ・コミットへ出さない。ネットワーク障害時は cleanup の再実行が必要になる。
