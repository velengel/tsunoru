# Story 0003: ログインなしでイベントを作る

Status: completed

Date: 2026-09-01

Product sequence: Story 1

## context

Dioxusでブラウザー表示できるRustフロントエンド基盤は完成した。
しかし、現在の画面はアプリケーションシェルだけであり、TSUNORUの利用者はまだイベントを作れない。

First Instructionの最初のプロダクトStoryでは、主催者がログインせず、集まりの名前、任意のひとこと、候補日時を入力する。
作成後は回答者へ渡せる共有URLを得る。

共有URLは別のブラウザーからも同じイベントを開けなければならない。
そのため、ブラウザー内だけではなく、サーバーの永続ストレージへイベントを保存する必要がある。

## definition of done

- ログインしていない主催者が、イベント名、任意の主催者のひとこと、一件以上の候補日時を入力できる。
- 候補日時は、スマートフォンでOSのカレンダーと時刻選択を使える入力から追加できる。
- イベント名が空、または候補日時がない場合は、原因が入力欄と結び付いた日本語のエラーとして示される。
- 主催者のひとことを空にしたままイベントを作れる。
- 作成したイベントと候補日時がSQLiteへ一つのトランザクションで保存される。
- 作成後に、主催者権限を含まない回答用の共有URLが表示される。
- 共有URLを再読み込みした場合と、別のブラウザーコンテキストで開いた場合に、イベント名、ひとこと、全候補日時を確認できる。
- 開発サーバーを再起動しても作成したイベントを開ける。
- 保存に失敗した場合は入力内容が画面に残り、再試行できる。
- 共有URLを開くまでの経路に、ログイン、プロフィール作成、カレンダー連携を要求しない。
- 320px幅で横スクロールせず、キーボードだけでも主要操作を完了できる。
- 利用者に見える受け入れテストと、保存境界のテストが実装より先に追加され、期待した理由で失敗している。
- test、Clippy、format、Fullstack build、秘密情報検査が成功する。
- 既存の安定版サーバーを止めずに候補版を別ポートで起動し、HTTPと実ブラウザーで検証してから切り替える。

## concern

- 共有URLはURLを知る人が閲覧できるため、秘密情報を置く場所にはならない。
- ログインなしの主催者権限は端末内のcapabilityに依存し、ブラウザーデータを消すと復旧できない。
- SQLiteは単一ホストの初期MVPには適するが、複数サーバーへ水平分散する場合は保存先の移行が必要になる。
- 開始日時だけを扱うため、予定の終了時刻はカレンダーへ持ち帰る利用者が補う必要がある。
- IANAタイムゾーンを自動取得できないブラウザーでは、日時の解釈を誤らないフォールバックが必要になる。
- 回答、集計、日程決定は後続Storyの範囲であり、このStoryだけでは日程調整を完遂できない。
