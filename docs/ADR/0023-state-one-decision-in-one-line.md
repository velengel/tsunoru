# ADR 0023: 今後のADRでは決定を一行で述べる

Status: accepted

Date: 2026-09-02

## context

ADR 0005とADR 0012では、`decision` に主判断、実装方法、例外、API、画面挙動が並ぶ。
個々の記述は必要だったが、何を決めたADRなのかを一読で判別しにくい。

ADRの各節には役割がある。
判断が必要になった背景は `context`、採用しなかった案は `rejected options`、受け入れる不利益は `consequences` に置けば、`decision` は採用した判断に集中できる。

## decision

今後作るADRの `decision` は、採用した一つの判断を一行で述べる。

### 補足

- 決定の適用条件を失うと誤読される場合だけ、不可欠な条件を補足する。
- 独立した判断が複数ある場合はADRを分ける。
- 既存のaccepted ADRは当時の記録として書き換えない。

## rejected options

### 従来どおり詳細を `decision` に列挙する

実装時に一箇所だけ読めば済むが、主判断と手段の区別が消える。
変更理由やリスクを各節へ置く構造も生かせない。

### 既存ADRも同じ形式へ書き換える

全体の見た目は揃うが、過去に何をどう記録したかという履歴を変更する。
今回の目的は今後の読みやすさであり、既存記録の再編集ではない。

### 文字数や行数だけを機械的に制限する

形式は揃うが、適用範囲を欠いた短文も通る。
一つの判断かどうかを基準にし、長さだけを合否に使わない。

## consequences

- ADR一覧と `decision` を短時間で読み比べられる。
- 理由、選択肢、リスクの置き場所が明確になる。
- 書き手は、主判断と実装詳細を分ける必要がある。
- 独立した判断を分けるため、ADRの件数が増える場合がある。
