# ADR 0068: Rust設計レビューは公式資料を優先する共有スキルで助言する

## context

Rust系の設計判断は、言語仕様、crate API、Dioxus、Tokio、SQLx、Cloudflare Workersのバージョン差や実行環境差の影響を受ける。記憶だけのレビューでは現行仕様とリポジトリ境界を取り違えるリスクがある。

## decision

Rust系の設計・実装・レビューでは`rust-expert`スキルを呼び出し、公式ドキュメントを第一根拠、一次フォーラムを補助根拠として判断と検証を記録する。

## rejected options

- モデルの記憶だけで助言する：API更新やruntime差分を見落とす。
- 一般的なブログを第一根拠にする：仕様上の保証と個人の推奨を区別しにくい。
- スキルを暗黙の意味推定だけで呼ぶ：重要な設計レビューで起動漏れが起きる。

## consequences

設計・レビュー時の調査コストは増えるが、根拠URL、該当行、検証境界を残せる。公式資料が不足する場合は一次フォーラムを使うが、推測は推測として明示する。スキル自体は認可やデプロイの権限を与えない。
