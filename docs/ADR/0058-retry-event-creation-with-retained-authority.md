# ADR 0058: イベント作成も同じ権限と内容で再送する

## context

スマホの通信が途切れると、Worker が保存していてもブラウザーは成功を受け取れない。送信のたびに別 ID や主催者鍵を作ると、重複イベントや主催者権限を失ったイベントが残る。#10 は回答の同内容再送を保証する一方、イベント作成の再送は409だった。

## decision

イベント ID・主催者 capability・正規化した作成内容を送信前から保持し、同じ組の再送だけを同じイベントの成功として返す。

## rejected options

- 再試行ごとに新しい ID と鍵を生成する。通信不良のたびに別のイベントが生まれる。
- ID の一致だけで既存イベントを成功として返す。主催者権限と内容の一致を確認できない。
- 保存に失敗したブラウザーからも作成する。再読込後に主催者権限を復元できない。

## consequences

Worker は主催者 hash と作成 payload hash を照合し、同内容なら200、初回は201、権限・内容の差は409とする。候補の追加と再送判定は同じ D1 batch で行う。ブラウザーは pending 作成と回答を自身の origin の保存領域に保持し、保存できない場合は送信を始めず具体的なエラーを表示する。これはイベント編集や権限回復リンクの導入ではない。

根拠: [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)、[ADR 0052](0052-save-complete-responses-by-capability.md)。
